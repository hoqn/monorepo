# HANDOFF.md

새 세션이 이 패키지를 이어받을 때 먼저 읽는 문서. 디자인 시스템 규칙은 `AGENTS.md`,
제품 기획은 `docs/product-spec.md`에 있다.

---

## 1. 지금 상태

`hoqn/monorepo`의 `packages/judo-log`. Astryx 기반 React + **TypeScript** 앱.
`pnpm run build` 통과. **상태는 localStorage에 저장돼 새로고침해도 남는다.**

```bash
pnpm install                  # 저장소 루트에서
pnpm --filter @hoqn/judo-log dev
pnpm --filter @hoqn/judo-log build      # 커밋 전 반드시 통과시킬 것
pnpm --filter @hoqn/judo-log exec astryx doctor
```

배포는 `.github/workflows/pages-deploy.yml`이 맡는다. GitHub Pages는 매 배포마다 사이트
전체를 교체하므로 워크플로 하나에서 judo와 judo-log를 함께 조립한다. 서비스를 추가할 때는
이 워크플로에 빌드 스텝과 복사 경로를 더할 것. **서비스마다 워크플로를 따로 만들면 나중에
배포된 쪽이 앞의 것을 지운다.** 공개 경로는 `/monorepo/judo-log/`다.

## 2. 이 앱이 뭔지

주 1~2회밖에 도장에 못 가는 직장인 유도 입문자가, **출퇴근길에 머리로 유도를 계속 굴리게
만드는 앱**. 몸 연습은 도장에서만 된다. 기억 유지와 상황 판단은 지하철에서도 된다.
그 빈틈만 노린다.

```
[도장, 30초]        [출퇴근길, 5~10분]      [출퇴근길, 3~5분]
  빠른 기록     →       정리하기        →       복습
 기술 태그만 톡톡    기억 짜내서 메모      간격 반복 카드
                    = 이미 1회차 복습
```

## 4. 뒤집지 말아야 할 제품 결정

여러 번 갈아엎으면서 남은 것들이다. 각각 이유가 있으니 바꾸려면 이유부터 반박할 것.

**입력을 두 단계로 쪼갠다.** 도장에서 긴 회고를 쓰는 사람은 없다. 거기선 태그만 찍고(30초),
정리는 출퇴근길에 한다. 기록 자체가 안 쌓이면 앱이 굶어 죽는다.

**정리하는 행위가 첫 번째 복습이다.** 그래서 정리 화면에서 표준 설명은 기본으로 접혀 있다.
먼저 보여주면 베껴 쓰고 끝나서 인출 연습이 사라진다. `Organize`의 `isStandardOpen` 기본값을
`true`로 바꾸지 말 것.

**사용자가 쓴 문장이 그대로 카드 뒷면이 된다.** "내 메모" 카드 유형이 그것이다. 이게 없으면
정리할 이유가 없어서 루프가 안 닫힌다.

**카드는 4종 + 내 메모다.** 명칭(암기) / 순서(절차 회상) / 상황(판단) / 심상(이미지 트레이닝).
유도는 절차 기억이라 단어장식 앞뒤 뒤집기로는 안 된다. 지하철에선 몸을 못 쓰므로 심상 카드가
의외로 주력이다.

**한국어 명칭이 주, 일본어는 보조.** 다만 사범님은 "오소토!"라고 외치므로 일본어를 버리면 안 된다.

**별칭(alias) 필드는 필수다.** 검색은 한국어 · 별칭 · 일본어 · 로마자 · 한자를 전부 매칭한다.

**진입점은 하나다.** 홈의 "시작" 하나로 정리 → 복습을 앱이 순서 정해서 태운다.

**표준 설명은 지어내지 않는다.** `techniques.ts`에서 `steps`/`mistakes`가 빈 기술은 이름 정보만
있는 것이고, 화면은 "표준 설명이 없다"고 말한다. 채울 때는 공신력 있는 출처를 확인하고 채울 것.

## 5. Astryx에서 실제로 걸렸던 것

`AGENTS.md`의 규칙 외에:

**TypeScript로 옮기면서 prop 값 오류가 컴파일 타임에 잡히게 됐다.** 예전에 런타임까지
흘러갔던 `Badge variant="accent"` / `Text size="xs"` / `Text color="error"` 같은 것들이다.
전환 과정에서 `TopNavHeading`이 실제로는 `label`이 아니라 `heading`을 받는다는 것도 이때 드러났다.
그래도 **컴포넌트를 쓰기 전에 `astryx component <이름>`으로 prop을 대조하는 습관은 유지할 것.**

**`Theme`의 import 경로는 소문자다.** 실제 export는 `@astryxdesign/core/theme`.

**`@vitejs/plugin-react`는 설치되지 않는다.** astryx CLI가 물고 있는 jscodeshift의 Babel 버전과
충돌한다. `@vitejs/plugin-react-swc`로 우회한 상태다. 되돌리지 말 것. (빌드 로그에 swc 대신
plugin-react를 권하는 안내가 뜨지만 무시해도 된다.)

**Astryx에는 모바일 네이티브 패턴이 없다.** 하단 탭 바가 없어서 상단 `TopNav`로 갔다.
모바일 대응은 `MobileNav` 드로어와 `BottomSheet` 둘뿐이다. 지하철에서 한 손으로 쓰는 앱으로는
인체공학이 아쉬우니, 플로우를 `BottomSheet`로 옮기는 건 여전히 검토해볼 만하다. (미착수)

## 7. 아직 안 된 것

우선순위 순.

**음성 메모가 없다.** 기획서 7장 화면 3에 있는 기능이다. MediaRecorder로 녹음은 되지만 오디오를
localStorage에 넣을 수 없어서(용량) IndexedDB 저장 계층이 따로 필요하다. 저장 방식이 로컬 전용으로
정해졌으니 이제 착수 가능하다.

**수련 전 브리핑 화면이 없다.** 기획서 7장 화면 7. 수련 요일은 이미 받고 있으니(`Settings`)
지난 지적사항 + 숙련도 낮은 기술로 3분 브리핑을 조립하면 된다. 기획서 10장에서 v1.1로 미룬 항목.

**숙련도가 연습 횟수뿐이다.** 기획서 7장 화면 5는 복습 성적까지 반영하고 "줄어들 수 있어야"
한다고 본다. `reviewLog`에 자기평가가 쌓이고 있으니 재료는 있다.

**기기 간 동기화가 없다.** 로컬 전용으로 결정했다(아래 9번). 나중에 붙인다면 지금 구조가
로컬 우선 베이스라 그 위에 얹으면 된다.

**온보딩이 없다.** 기획서 9장은 가입 시 수련 경력을 받자고 한다. 지금은 그냥 공통 카드 30장을
사흘에 나눠 깔고 시작한다. 기획서 11장의 "이건 몸 연습을 대체하지 않는다" 고지도 아직 없다.

## 8. 시도했다가 버린 것

같은 길을 다시 가지 말라고 남긴다.

**커스텀 비주얼 아이덴티티 두 번 반려됐다.** 어두운 남색 + 금색 액센트 버전, 그리고 도복 직물
버전. 매일 지하철에서 5분 쓰는 개인 도구에 세계관을 입힐 이유가 없다는 판단으로 표준 디자인
시스템으로 전환했다. **다시 커스텀 테마를 제안하지 말 것.**

**iOS HIG를 손으로 구현한 버전도 있었다.** 인체공학은 이게 제일 나았지만, 유지보수와 접근성
때문에 디자인 시스템으로 옮겼다.

**띠 색 5칸 숙련도 막대는 뺐다.** 게임화 토큰이고 실제 승단 체계와 의미가 겹쳐 헷갈린다.

**앱이 자기 설계 철학을 설명하는 문구를 대폭 줄였다.** 늘리지 말 것.

## 9. 정해진 것

- **저장 방식: 로컬 전용(localStorage).** 기획서 10장 v1 범위와 일치하고, 이 저장소는 GitHub Pages
  정적 배포라 서버가 없다. 기기 간 동기화는 나중에 이 위에 얹는다.
- **TypeScript로 전환.** 모노레포가 TS 기반이고, 5장의 prop 오류들이 컴파일 타임에 잡힌다.
- **패키지·서비스 이름: `judo-log` (`@hoqn/judo-log`).** 화면에 보이는 앱 이름은 "유도 복습"이다.

## 10. 사람에게 물어야 할 것

**데아시바라이(出足払)의 국내 공식 명칭.** 자료마다 갈려서 기술 DB에서 뺐다. 도장에서 사범님께
확인 필요. 모두걸기(送足払, 오쿠리아시바라이)와는 **다른** 기술이다.

**표준 설명이 빈 기술 21개.** `techniques.ts`에서 `steps`/`mistakes`가 빈 배열인 것들이다.
이름은 기획서 부록 대조표에서 왔지만 동작 절차는 출처 확인 전까지 채우지 않았다.

**낙법·예법 카드의 깊이.** 지금은 이름과 심상 유도까지만 담았다. 지도자 없이 글로 따라 하면
다치는 영역이라 앱이 표준 설명을 자처할 자리가 아니라고 봤는데, 도해까지 갈지는 사람이 정할 일.
