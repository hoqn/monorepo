# 유도 3D 실험실 (judo-3d-lab) — PoC

유도 연습 앱을 만들기 전에 다음 두 가지를 확인하려고 만든 실험 프로젝트입니다.

1. 기술 자세를 영상이 아니라 **3D 모델**로 만들어, 원하는 각도와 속도로 볼 수 있는가?
2. 그 3D 자세로 **무게중심·균형 분석**을 할 수 있는가?

```bash
pnpm --filter @hoqn/judo-3d-lab dev     # http://localhost:5173
pnpm --filter @hoqn/judo-3d-lab test    # 수학 코어 단위 테스트
pnpm --filter @hoqn/judo-3d-lab build
```

URL 파라미터를 붙이면 특정 기술·시각·시점으로 바로 열립니다. 예: `/?tech=seoi-nage&t=2.2&view=side#technique`

## 결론 요약

**가능합니다.** 3D 표시와 무게중심 분석은 이 정도 코드로도 웹(모바일 포함)에서 실시간으로 돌아갑니다.
어려운 것은 **정확한 동작 데이터를 어떻게 확보하느냐**이고, 제품의 품질과 비용은 그 선택에서 정해집니다.
자세한 비교와 다음 단계는 앱의 "결론·다음 단계" 탭(`src/experiments/About.tsx`)에 정리했습니다.

## 실험

| 탭 | 내용 | 확인한 것 |
| --- | --- | --- |
| ① 기술 3D 뷰어 | 밭다리후리기(大外刈)·업어치기(背負投)·안다리후리기(大内刈)를 토리·우케 두 사람의 키프레임 애니메이션으로 재생. 시점 전환, 슬로모션, 단계(쿠즈시→츠쿠리→카케→낙법)로 이동. 두 사람의 겹침을 풀고 맞닿은 지점을 표시 | 두 사람 기술을 3D로 보여줄 수 있고, 손이 IK로 상대 깃·소매에 붙어 있어 보간 중에도 잡기가 유지됨 |
| ② 자세·무게중심 | 슬라이더로 자세를 바꾸면 질량중심·기저면·안정 여유가 즉시 갱신. 자연체·자호체·무너진 자세 프리셋 | 분절 질량 표 기반 질량중심 계산이 직관적인 교육 자료가 됨 |
| ③ 영상→3D 추출 | MediaPipe Pose Landmarker로 사진·영상에서 3D 관절을 추정한 뒤 ①·②와 같은 분석을 적용 | 한 사람은 실용 수준. 두 사람이 엉키는 장면과 깊이 방향 정확도가 한계 |

## 구조

```
src/
  body/
    points.ts          모든 데이터의 공통 표현: 이름 붙은 3D 점 23개(BodyPoints)
    rig.ts             포즈 명세(골반·상체·발 위치·잡기) → BodyPoints. 다리·팔은 2관절 IK
    anthropometry.ts   de Leva(1996) 분절 질량 표 → 전신 질량중심
    balance.ts         기저면(발바닥 접촉점 볼록 껍질), 안정 여유, XCoM(Hof 2005)
    contact.ts         두 사람 겹침 풀기(캡슐 충돌 + 위치 기반 동역학)와 접촉 지점 찾기
    fromMediapipe.ts   MediaPipe 랜드마크 → BodyPoints
  techniques/
    timeline.ts        키프레임 보간(Hermite) · 단계 정의
    common.ts          기술 공통 출발 자세(자연체·맞잡기)와 좌표 규칙
    osoto-gari.ts      밭다리후리기 키프레임
    seoi-nage.ts       업어치기 키프레임 (토리 180° 회전, 우케 공중 회전)
    o-uchi-gari.ts     안다리후리기 키프레임
    index.ts           기술 목록
    analyze.ts         시점별 질량중심·속도·균형 계산
  scene/               three.js(react-three-fiber) 렌더링: 도복 입은 절차적 마네킹, 질량중심·기저면 오버레이
  components/          기저면 지도·안정성 그래프(SVG), 균형 카드
  ui/tokens.ts         화면에서 쓰는 의미별 색(Astryx 토큰)과, 3D 재질용으로 토큰을 실제 색으로 바꾸는 훅
  experiments/         탭별 화면
  astryx-themes.ts     `astryx theme add neutral --import`가 생성 (직접 수정 금지)
```

핵심 설계는 **데이터 출처와 분석의 분리**입니다. 수작업 키프레임이든 영상 추정이든, 앞으로 쓸 모션캡처든
모두 `BodyPoints`로 바꾸기만 하면 렌더링과 분석을 그대로 재사용할 수 있습니다.

### 분석 방법

- **질량중심(CoM)**: 16개 분절(머리, 몸통 3분할, 위팔·아래팔·손, 넙다리·종아리·발)의 질량중심을 질량 비율로 가중 평균합니다.
- **기저면(BoS)**: 바닥에서 6cm 이내에 있는 발바닥 모서리 점들로 볼록 껍질을 만듭니다.
- **정적 안정 여유**: CoM 바닥 투영점이 기저면 경계 안쪽으로 얼마나 들어와 있는지(m). 음수면 기저면 밖입니다.
- **동적 안정 여유(XCoM)**: `CoM + v/ω0` (ω0 = √(g/l)). 속도를 반영해 "발을 옮기지 않고 버틸 수 있는가"를 판정합니다.
  쿠즈시는 상대가 움직이는 중에 균형을 무너뜨리는 것이므로, 정적 지표보다 이쪽이 체감에 가깝습니다.

### UI · 디자인 시스템

화면은 [Astryx](https://www.npmjs.com/package/@astryxdesign/core) 컴포넌트와 neutral 테마로 만듭니다. 규칙은 `.claude/CLAUDE.md`에 있습니다.

- 앱 틀은 `AppShell` + `TopNav`, 각 실험은 `Layout`(헤더 툴바 / 3D / 오른쪽 패널 / 타임라인)으로 짭니다. 직접 쓴 CSS 파일은 없습니다.
- 색은 모두 토큰입니다. 토리·우케는 차트 계열 색(`--color-data-categorical-orange`·`-purple`)으로, 3D 마커·그래프·지도·카드에서 같은 색입니다.
  three.js 재질은 CSS 변수를 읽지 못하므로 `useResolvedColors`로 계산된 색을 넘깁니다. 도복 색(흰색·파란색)만 3D 재질 고유 색입니다.
- 라이트·다크 모드는 OS 설정을 따릅니다. Astryx 내장 문구는 `ko-KR` 카탈로그로 한국어로 나옵니다.
- 반응형: 폭 1024px 이하에서는 오른쪽 패널이 `BottomSheet`로 바뀌고, 768px 이하에서는 상단 탭이 모바일 메뉴로 접힙니다.
- Astryx는 `--import` 테마 흐름을 쓰려고 canary 버전(`0.6.6-canary.cc5573c`)에 고정했습니다. 정식판에 들어오면 올려야 합니다.

### 마네킹과 접촉

- **마네킹**: 스키닝 없이 관절점 사이마다 단면 반지름이 변하는 회전체를 이어 붙여 만듭니다(넓은 가슴·잘록한 허리, 근육 굴곡, 상의 자락·깃·소매, 띠 매듭, 얼굴 방향).
  점만 있으면 그릴 수 있어 영상 추정 결과에도 그대로 씁니다.
- **겹침 보정**: 키프레임은 각자 따로 풀리므로 두 사람이 서로 파고들 수 있습니다. 매 프레임 몸을 캡슐 16개로 근사해 겹친 곳을 밀어내고,
  뼈 길이와 바닥을 딛은 발은 유지합니다. 몸통은 하나의 강체로 움직입니다. 손은 깃·소매를 잡아야 하므로 충돌에서 뺍니다.
  겹침을 풀 때는 동작을 주도하는 쪽(기본: 토리, 단계별로 `contactLead`로 지정)을 무겁게 두어 상대가 더 많이 밀립니다.
  그래야 후리기처럼 일부러 다리를 부딪히는 순간 후리는 다리가 엉뚱하게 빠지지 않고 우케 다리가 쓸려 나갑니다.
  깊게 관통하는 키프레임은 방향을 판단할 수 없으므로, 보정에 기대지 말고 키프레임 자체를 고칩니다(필요하면 경유 키프레임 추가).
  보정 후 맞닿은 지점은 "지금 맞닿은 곳" 목록과 3D 표시로 보여 줍니다. 뷰어의 "겹침 보정" 토글로 보정 전후를 비교할 수 있습니다.

### 한계

- 기술 키프레임은 시범 영상을 보고 손으로 옮긴 근사치입니다. 실측 데이터가 아니므로 숫자는 경향을 보는 용도로만 쓰세요.
- 겹침 보정은 몸을 밀어내기만 합니다. 잡고 당기는 힘, 도복이 늘어나고 구겨지는 모습은 표현하지 않습니다.
- 무게중심은 남성 표준 비율을 씁니다. 도복, 체형 차이, 잡기로 오가는 힘(외력)은 반영하지 않습니다.
- 영상 추출(③)은 카메라 한 대로 깊이를 추정하므로 앞뒤 오차가 큽니다. 두 사람의 상대 위치는 좌우 방향만 대략 복원합니다.
- MediaPipe 모델 파일(6~30MB)은 처음 분석할 때 `storage.googleapis.com`에서 받아옵니다. WASM 런타임은 번들에 포함됩니다.
